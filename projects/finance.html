财务核验处理流程数据正确性可恢复执行技术与验收演示范围

现有资料为私有财务处理归档。下述服务与恢复架构属于参考案例设计；首页提供独立的虚构数据核验样例。

处理流程

标准化解析多来源文件，统一字段、日期和金额单位。
核验按确认粒度关联，分类缺失、重复和金额差异。
追溯输出明细、汇总和异常，保留批次与原始来源。

数据正确性

  • 编号按文本处理，区分空值、零值和解析失败。源文件已损失的精度不能通过格式转换恢复。
  • openpyxl 读取公式与缓存，不承担公式重算。确认过的业务公式转换为确定性规则，无法确认的结果阻止进入正式报表。
  • 金额以 Decimal 计算并明确定标存储与舍入阶段。多笔充值与消耗先按业务粒度聚合，避免关联展开造成重复累计。

可恢复执行

分别识别重复文件、重复业务记录和重复任务。分批数据与检查点在同一数据库事务内提交，重跑时复用已完成的标准化结果。

文件生成与数据库提交不是同一事务。报表先形成版本化产物，再登记为可下载；中断后核对产物与登记状态，不将半成品显示为完成。

技术与验收

Python / FastAPI 提供任务接口，openpyxl / csv 解析文件，Decimal 完成金额计算，SQLite 保存批次与检查点。WorkBuddy Skill 仅提供调用入口。

验收覆盖重复输入、主键冲突、公式缓存、金额舍入及处理中断；不将文件生成成功等同于业务核验通过。

演示范围

首页样例在浏览器内将金额文本转换为整数分，核对同一业务编号的两份数据，并区分差额、缺失与重复。重复记录不会被直接相加掩盖。

样例不读取真实表格、不执行记账或付款。原始公司报表保持私有。
